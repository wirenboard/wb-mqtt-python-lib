## Как устроена библиотека

Основной объект библиотеки это [клиент](#клиент) `Client`. Сервис создаёт и подключает его при запуске, клиент держит соединение с брокером всё время работы сервиса и сам переподключается после обрыва. По умолчанию клиент подключается к брокеру через unix-сокет, и сервису на контроллере пароль брокера не нужен.

[Свои устройства](#свои-устройства) сервис создаёт через клиента, а библиотека публикует их по [конвенции Wiren Board](https://github.com/wirenboard/conventions).

[Чужие устройства](#чужие-устройства), то есть устройства других драйверов, сервис получает у клиента по адресу, например `wb-mr6c_10/K1`. Их значения, мета и ошибки приходят из брокера и обновляются в объектах сами. Запись в чужой контрол уходит командой в `/on`, и выполняет её драйвер этого устройства.

[Свои и чужие устройства](#свои-и-чужие-устройства) описывают одни классы `Device` и `Control`. Объект можно получить, даже если устройства ещё нет.

На события сервис отвечает [обработчиками](#обработчики-событий), которые назначает на объекты методами `on_*`. Например, команда из `/on` своего контрола приходит в `on_command`, а новое значение чужого контрола в `on_value`.

Для работы с топиками вне конвенции есть [сырые методы](#работа-с-mqtt-вне-конвенции) `client.raw`.


## Порядок работы

1. Создать клиента с именем драйвера сервиса и подключиться.
2. Создать свои устройства и их контролы.
3. Получить чужие устройства и контролы, которые нужны сервису.
4. Назначить обработчики на команды своих контролов и на изменения чужих.
5. Перед отключением можно удалить свои устройства, иначе они останутся в веб-интерфейсе.


## На что обратить внимание

- Сервис работает через один клиент. Дополнительные клиенты создают, только если часть устройств должна быть под другим именем драйвера. У каждого клиента должно быть своё имя драйвера. Раздел [Клиент](#клиент).
- Обработчик объявляют один раз. Раздел [Обработчик объявляют один раз](#обработчик-объявляют-один-раз).
- `on_value` при назначении сразу получает текущее значение, поэтому при запуске сервису не нужно отдельно читать значения. Раздел [Срабатывание обработчиков при назначении](#срабатывание-обработчиков-при-назначении).
- Команда в `/on` своего контрола сама значение не меняет, его записывает обработчик через `set_value`. Раздел [Команды](#команды).
- Своё устройство библиотека в брокере не слушает, правку извне объекты не видят. Раздел [Свои и чужие устройства](#свои-и-чужие-устройства).


## Быстрый старт

В примере ниже сервис `wb-mqtt-load-alarm` включает аварию, когда нагрузка процессора выше порога. Среднюю нагрузку публикует сервис wb-mqtt-metrics. Наш сервис создаёт своё устройство с двумя контролами, порогом и аварией, а порог пользователь меняет в веб-интерфейсе. Библиотека подключена к сервису, как описано в разделе [Подключение к сервису](#подключение-к-сервису).

```python
import asyncio
import contextlib
import logging
import signal
from typing import Any

from wb.mqtt_load_alarm.wb_mqtt_lib import (
    BrokerDisconnectedError,
    Client,
    Control,
    ControlType,
)

THRESHOLD_MIN = 0
THRESHOLD_MAX = 10


async def run() -> None:
    # Вход в async with ждёт подключения к брокеру,
    # сигнал остановки прерывает и это ожидание
    async with Client(driver="wb-mqtt-load-alarm") as client:
        try:
            # Своё устройство, оно появится в веб-интерфейсе
            device = await client.create_device(
                "load_alarm", title={"en": "Load Alarm", "ru": "Нагрузка"}
            )
            threshold = await device.create_control(
                "threshold",
                control_type=ControlType.RANGE,
                title={"en": "Threshold", "ru": "Порог"},
                value=2,
                maximum=THRESHOLD_MAX,
                minimum=THRESHOLD_MIN,
            )
            alarm = await device.create_control(
                "alarm",
                control_type=ControlType.ALARM,
                title={"en": "High Load", "ru": "Высокая нагрузка"},
                value=False,
                readonly=True,
            )
            # Контрол другого сервиса, его публикует wb-mqtt-metrics
            load = await client.get_control("metrics/load_average_1min")

            # Пользователь поменял порог в веб-интерфейсе
            async def threshold_command(control: Control, value: Any) -> None:
                is_number = isinstance(value, (int, float))
                if is_number and THRESHOLD_MIN <= value <= THRESHOLD_MAX:
                    await control.set_value(value)

            # Поменялась нагрузка или порог
            async def check(control: Control, value: Any, previous: Any) -> None:
                if load.value is not None:
                    await alarm.set_value(load.value > threshold.value)

            threshold.on_command(threshold_command)
            load.on_value(check)
            threshold.on_value(check)

            # Вариант с декораторами. Функцию назначают при объявлении,
            # и три строки выше не нужны
            # @threshold.on_command
            # async def threshold_command(control: Control, value: Any) -> None:
            #     ...
            #
            # @load.on_value
            # @threshold.on_value
            # async def check(control: Control, value: Any, previous: Any) -> None:
            #     ...

            # Сервис работает, пока его не остановят сигналом
            await asyncio.Future()
        finally:
            # Перед выходом сервис стирает своё устройство,
            # чтобы оно не осталось в веб-интерфейсе
            with contextlib.suppress(BrokerDisconnectedError):
                await client.remove_driver_devices()


async def main() -> None:
    # SIGTERM от systemd и Ctrl+C отменяют главную задачу,
    # и сервис выходит через finally
    task = asyncio.current_task()
    loop = asyncio.get_running_loop()
    for signal_number in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(signal_number, task.cancel)
    with contextlib.suppress(asyncio.CancelledError):
        await run()


if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    asyncio.run(main())
```

- `create_device` и `create_control` публикуют устройство сервиса и его контролы. Если в брокере осталось устройство сервиса с прошлого запуска, библиотека сначала стирает его.
- `get_control` отдаёт объект контрола, даже если wb-mqtt-metrics ещё не запущен. Значение в объекте появится, когда wb-mqtt-metrics его опубликует.
- `on_value` вызывает обработчик сразу при назначении, если у контрола уже есть значение, а потом на каждое изменение. Поэтому при запуске сервису не нужно отдельно читать значения. `check` назначена и на нагрузку, и на порог, поэтому авария пересчитывается, когда меняется любой из них.
- Когда пользователь меняет порог в веб-интерфейсе, библиотека вызывает `threshold_command` с новым значением. Сама библиотека значение порога не меняет, его записывает обработчик через `set_value`. Перед записью обработчик проверяет, что пришло число в допустимых пределах, потому что команду может прислать и правило или другой сервис с любым значением.
- systemd останавливает сервис сигналом SIGTERM. Без своего обработчика сигнала Python завершается сразу и не доходит до `finally`, поэтому `main` ставит обработчик. Он отменяет главную задачу, `await asyncio.Future()` прерывается, `finally` стирает устройство, а выход из `async with` закрывает клиент.


## Подключение к сервису

Библиотека работает на Python 3.13 с [aiomqtt](https://github.com/empicano/aiomqtt) 2.x, на контроллерах Wiren Board с Debian trixie.

Библиотеку добавляют git-сабмодулем в корень репозитория сервиса, а при установке она попадает внутрь пакета сервиса, например в `wb.mqtt_example.wb_mqtt_lib`.

```bash
# Добавить библиотеку сабмодулем
git submodule add https://github.com/wirenboard/wb-mqtt-python-lib.git wb-mqtt-python-lib
# Закрепить нужную версию библиотеки
git -C wb-mqtt-python-lib checkout <коммит>
# В коммит сервиса попадает файл .gitmodules и хэш сабмодуля
git add .gitmodules wb-mqtt-python-lib
```

В `setup.py` сервиса пакет библиотеки добавляют к пакетам сервиса.

```python
from setuptools import find_namespace_packages, setup

LIB_PACKAGE = "wb.mqtt_example.wb_mqtt_lib"

setup(
    name="wb-mqtt-example",
    packages=find_namespace_packages(include=["wb.*"]) + [LIB_PACKAGE],
    package_dir={LIB_PACKAGE: "wb-mqtt-python-lib/wb_mqtt_lib"},
)
```

Сервис импортирует библиотеку из своего пакета.

```python
from wb.mqtt_example.wb_mqtt_lib import Client, ControlType
```

Остальное в репозитории сервиса:

- В `debian/control` в `Depends` нужен `python3-asyncio-mqtt`, сабмодуль свои зависимости сам не приносит. Если тесты сервиса при сборке импортируют библиотеку, тот же пакет нужен и в `Build-Depends`.
- Клон сервиса делают с `--recurse-submodules` или после клона вызывают `git submodule update --init`.

Новая версия библиотеки доходит до сервиса только бампом сабмодуля.

```bash
# Забрать новые коммиты библиотеки
git -C wb-mqtt-python-lib fetch
# Перейти на нужный коммит
git -C wb-mqtt-python-lib checkout <коммит>
# В PR сервиса будет видна только смена хэша
git add wb-mqtt-python-lib
```


## Клиент

```python
Client(driver: str, broker_url: str = DEFAULT_BROKER_URL)
```

`driver` это имя драйвера сервиса. Библиотека пишет его в мету каждого своего устройства и по нему находит устройства сервиса, в том числе оставшиеся от прошлого запуска.

По умолчанию `broker_url` равен `unix:///var/run/mosquitto/mosquitto.sock`, это сокет брокера на контроллере, и пароль сервису не нужен. Другой адрес, например брокера на другой машине или тестового брокера, пишется так:

- `tcp://host:port`. `mqtt-tcp://host:port` значит то же самое.
- `ws://host:port/path`. Путь уходит в запрос websocket, без него клиент идёт на `/mqtt`.
- `unix:///path/to/socket`, путь после трёх косых.
- Логин и пароль пишутся перед хостом, `tcp://user:password@host:1883`. Символы `/`, `?`, `#`, `@`, `:` и `%` в них кодируются процентами, например `%2F` вместо `/`.

Неверный адрес даёт `ValueError` сразу при создании клиента. Клиент подключается по MQTT 5, и брокер по другому адресу должен его поддерживать. Соединения `tcp://` и `ws://` не шифруются, логин и пароль идут по сети открытым текстом.

Вход в `async with` ждёт первого соединения и повторяет попытки, пока брокер не ответит. Чтобы ждать не дольше заданного времени, клиент подключают через `connect()` с таймаутом. После `TimeoutError` клиент в фоне не переподключается.

```python
client = Client(driver="wb-mqtt-example")
try:
    # Ждать брокер не дольше 30 с
    await asyncio.wait_for(client.connect(), timeout=30)
except TimeoutError:
    logger.error("MQTT broker is not available")
    return
```

Если брокер отверг логин или пароль при первом подключении, вход бросает `LoginRejectedError`, и клиент больше не переподключается. После первого соединения клиент переподключается сам при любом обрыве, в том числе когда брокер отвергает логин. Пауза между попытками растёт от 0,5 до 30 с.

Сервису достаточно одного клиента. Дополнительный клиент нужен, только если часть устройств должна быть под другим именем драйвера, например чтобы удалять их через `remove_driver_devices()` отдельно от остальных. Устройства одного клиента для другого чужие.

У каждого клиента должно быть своё имя драйвера. Библиотека считает своими все устройства с именем своего драйвера, поэтому клиент с тем же именем может стереть устройства другого как свои. Второй клиент с тем же драйвером в том же процессе получит `ValueError` при подключении, пока первый не закрыт.

`client.connected` показывает, есть ли сейчас связь с брокером. Команда чужому контролу без связи не копится до переподключения, а сразу бросает `BrokerDisconnectedError`, поэтому эту ошибку ловят, а не проверяют `connected` заранее. Изменения своих устройств и retained-публикации `client.raw` без связи ошибки не дают, библиотека отправит их после переподключения.

`client.on_connection_change(handler)` сообщает о смене связи, это единственный обработчик клиента. Свои устройства и подписки библиотека восстанавливает сама, а событие нужно сервису, который сам что-то делает при обрыве. Например, он помечает устройства внешней системы недоступными, а после возврата связи запрашивает её состояние.

```python
async def link_changed(connected: bool) -> None:
    if connected:
        await bridge.request_state()
    else:
        await bridge.mark_unavailable()


client.on_connection_change(link_changed)
```

- `True` приходит после каждого подключения, когда клиент уже восстановил подписки. Обработчик, назначенный до `connect()` или до запуска цикла событий, получит `True` при первом подключении.
- `False` приходит один раз на обрыв, сколько бы неудачных попыток переподключения ни было после него.
- До первого подключения и при `close()` события нет.
- При назначении обработчик не вызывается, текущее состояние видно в `client.connected`.

Выход из `async with` или `close()` закрывает клиент. Клиент отменяет свои обработчики и фоновые задачи и закрывает соединение. Устройства сервиса остаются в брокере, удалить их сервис может сам перед выходом, как в [быстром старте](#быстрый-старт). Изменения, которые не дошли до брокера, например из-за обрыва связи, теряются.

Вызовы библиотеки, которые в это время ждут брокер в другом коде, например в главной задаче сервиса, бросают `ClientClosedError`.

Закрытый клиент снова не подключить. Для нового соединения нужен новый `Client`, и он начинает без устройств, подписок и обработчиков.

Если у сервиса свой жизненный цикл, например объект с методами `start` и `stop` или фикстура в тестах, клиент держат без `async with` и сами вызывают `connect()` и `close()`.

```python
class Service:
    def __init__(self, broker_url: str) -> None:
        self._client = Client(driver="wb-mqtt-example", broker_url=broker_url)

    async def start(self) -> None:
        await self._client.connect()
        device = await self._client.create_device("example", title="Example")
        relay = await device.create_control(
            "relay", control_type=ControlType.SWITCH, value=False
        )
        relay.on_command(self._relay_command)

    async def stop(self) -> None:
        with contextlib.suppress(BrokerDisconnectedError):
            await self._client.remove_driver_devices()
        await self._client.close()

    async def _relay_command(self, control: Control, value: Any) -> None:
        if isinstance(value, bool):
            await control.set_value(value)


async def main() -> None:
    task = asyncio.current_task()
    loop = asyncio.get_running_loop()
    for signal_number in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(signal_number, task.cancel)
    service = Service(DEFAULT_BROKER_URL)
    with contextlib.suppress(asyncio.CancelledError):
        try:
            await service.start()
            await asyncio.Future()
        finally:
            await service.stop()
```

`stop()` вызывают в `finally`, тогда он закроет клиент, даже если `start()` упал на середине. Когда сервис останавливают сигналом SIGTERM или SIGINT, обработчик из `main` отменяет главную задачу, как в [быстром старте](#быстрый-старт), и `finally` тоже вызывает `stop()`. Клиент можно создать и до запуска цикла событий, к брокеру он подключается только в `connect()`.


## Свои и чужие устройства

Свои и чужие устройства описываются одними классами `Device` и `Control`. Все объекты одного устройства или контрола одинаковые, в них одни и те же значения, и они равны по `==`, а `is` для сравнения не годится. Объект не нужно получать заново. Он работает и после перезапуска сервиса, который публикует устройство, и после переподключения клиента.

|                                                        | Своё                                                    | Чужое                                                                       |
| ------------------------------------------------------ | ------------------------------------------------------- | --------------------------------------------------------------------------- |
| Откуда состояние                                       | из кода сервиса, библиотека его публикует               | из брокера                                                                  |
| `control.set_value(value)`                             | значение в объекте меняется сразу и пишется в MQTT, только если изменилась строка в топике | команда публикуется в топик `/on`, значение в объекте изменится, когда драйвер опубликует новое |
| `set_error`, `update_meta`, `remove`, `create_control` | публикуют и стирают топики                              | бросают `NotOwnError`                                                       |
| `on_command`, `on_control_command`                     | команды из `/on`                                        | бросают `NotOwnError`                                                       |
| Когда приходят события                                 | в момент вызова в коде сервиса                          | когда из брокера пришло сообщение драйвера                                  |
| После переподключения                                  | библиотека публикует устройство заново                  | обработчики получают изменения за время обрыва, стёртого за обрыв библиотека не видит, раздел [Чужие устройства](#чужие-устройства) |
| Устройство изменили извне                              | библиотека правку не видит                              | обработчики получают правку                                                 |

Своё устройство библиотека в брокере не слушает. Если его удалили в веб-интерфейсе, поменяли другим сервисом или записали прямо в топик значения, объекты не меняются и событий нет.

Классы `Device` и `Control` нужны сервису для аннотаций типов. Сами объекты сервис получает от библиотеки, из `create_device`, `create_control`, `get_device`, `get_control`, `device.controls` и аргументов обработчиков. Вызов `Device(client, "dev")` бросает `TypeError`.

Объект привязан к имени устройства, а не к владельцу. Если чужое устройство пропало и сервис создал своё под тем же именем, обработчики, назначенные на чужое, продолжают работать уже со своим.

### Снимок и список устройств

| Вызов                              | Что делает                                                              |
| ---------------------------------- | ----------------------------------------------------------------------- |
| `client.get_device_names()`        | отдаёт имена всех устройств, которые сейчас есть в брокере, свои тоже   |
| `client.get_device_snapshot(name)` | отдаёт снимок устройства `DeviceSnapshot` или `None`, если устройства нет |

`DeviceSnapshot` содержит `name`, `title`, `driver`, `error` и `controls`, словарь «имя → `ControlSnapshot`», а у каждого `ControlSnapshot` есть `meta`, `value` и `error`. Контролы без меты в снимок не попадают, у `pushbutton` значения нет. Снимок хранит значения на момент вызова и потом не меняется.

### Ожидание значения

`await control.wait_value(expected, timeout)` ждёт, пока значение контрола станет равным `expected` или, если передана функция, пока она вернёт истину. Если значение уже такое, метод возвращается сразу, а по таймауту бросает `TimeoutError`. Его можно вызывать и из обработчика. У `pushbutton` значения нет, нажатие ждут через `on_value`. Дождаться `None` нельзя, стирание значения и пропажа контрола ожидание не завершают.

```python
relay = await client.get_control("wb-mr6c_10/K1", timeout=5)
await relay.set_value(True)
# Ждать, пока драйвер выполнит команду
await relay.wait_value(True, timeout=5)
```


## Свои устройства

```python
device = await client.create_device(
    "waterius_1", title={"en": "Waterius 1", "ru": "Ватериус 1"}
)
cold = await device.create_control(
    "cold_water",
    control_type=ControlType.VALUE,
    title={"en": "Cold Water", "ru": "Холодная вода"},
    value=0.0,
    precision=0.001,
    readonly=True,
    units="m^3",
)
await cold.set_value(12.3456)  # уйдёт как «12.346»
```

### Создание устройства

`client.create_device(name, title=None, force=False)` сначала проверяет, чьи топики лежат в брокере под этим именем. Если это топики своего драйвера, например от прошлого запуска с другим набором контролов, библиотека их стирает. Затем публикуется мета устройства с заголовком и именем драйвера клиента, а контролы появятся, когда сервис их создаст.

Если под именем лежит устройство другого драйвера или устройство без драйвера, `create_device` бросает `DeviceTakenError` и ничего не трогает. Остатки топиков, из которых устройство не собирается, например значения без меты, библиотека стирает.

С `force=True` библиотека стирает всё под именем, в том числе чужое, и публикует своё устройство. Это нужно, например, после смены имени драйвера или при переходе сервиса на библиотеку, если прежняя версия оставила под именем устройство без драйвера. Если другой драйвер ещё работает, он продолжит публиковать туда свои значения.

Без связи `create_device` бросает `BrokerDisconnectedError`. Повторное создание уже созданного устройства бросает `ValueError`.

### Создание контрола

`device.create_control(name, control_type, ...)` публикует мету контрола и начальное значение, если оно передано. Обязательны только `name` и `control_type`. Всё объявление проверяется до публикации, ошибка в любом поле не оставляет в брокере ничего.

- `name` — имя контрола.
- `control_type` — тип контрола из `ControlType`.
- `title` — заголовок, строка считается английской, на двух языках это `{"en": "...", "ru": "..."}`.
- `value` — начальное значение. Без него веб-интерфейс до первого `set_value` показывает заглушку, например `0` у числа и выключенный выключатель. У `pushbutton` значения нет, и любое `value` даёт `TypeError`.
- `maximum`, `minimum` — пределы для `range` и `value`, конечные числа.
- `precision` — положительное число, шаг поля ввода в веб-интерфейсе и округление значения в топике, раздел [Значения](#значения).
- `readonly` — `True`, если контрол не принимает команды. Это подсказка веб-интерфейсу, он не даёт менять такой контрол. Команды в `/on` от правил и других сервисов всё равно приходят, и `on_command` их получает.
- `units` — единицы измерения для `value` и `range`, строка.
- `order` — место на карточке, целое число, по умолчанию по порядку создания.
- `hidden` — `True`, чтобы спрятать контрол в веб-интерфейсе.
- `enum` — названия значений, `{"0": {"en": "Idle", "ru": "Ожидание"}, "1": ...}`.

Поля, которые к типу не относятся, например `minimum` у `text`, библиотека не отвергает и пишет в мету как есть. На значение они не влияют.

В `ControlType` десять действующих типов конвенции, это `SWITCH`, `WO_SWITCH`, `ALARM`, `PUSHBUTTON`, `RANGE`, `RGB`, `TEXT`, `LOCAL_TIME`, `W1_ID` и `VALUE`. Устаревшие типы вроде `temperature` создать нельзя, вместо них конвенция рекомендует использовать `value` с `units`. Элемент `ControlType` равен своей строке, поэтому `control.control_type == ControlType.SWITCH` работает и для чужого контрола, у которого тип пришёл из брокера строкой.

Имена устройств и контролов проверяются до первой публикации. Пустое имя, имя с `/`, `+`, `#` или управляющими символами и слишком длинное имя дают `ValueError`.

### Значения

`control.set_value(value)` проверяет значение по типу контрола, какие значения принимает каждый тип, показано в разделе [Значения по типам контрола](#значения-по-типам-контрола). Новое значение своего контрола сразу попадает в `control.value` и в события, а в MQTT пишется, только если изменилась строка в топике. У `pushbutton` публикуется каждое нажатие. Для чужого контрола значение уходит командой в `/on`.

Изменения уходят в брокер в порядке вызовов, в том числе из разных задач.

`set_value(None)` стирает значение своего контрола любого типа, кроме `pushbutton`. Библиотека публикует пустое retained-сообщение, `control.value` становится `None`, события нет.

Число с `precision` уходит с тем числом знаков после запятой, сколько их в `precision`, без нулей в хвосте. При `precision=0.1` значение 21.54 уходит как «21.5», а `control.value` и событие получают 21.54.

### Ошибки, мета и удаление

- `control.set_error(error)` ставит или снимает ошибку контрола. Ошибка это флаги `ControlErrorFlags.READ`, `WRITE` и `POLL`, их складывают через `|`, а `ControlErrorFlags.NONE` снимает ошибку. Сама библиотека ошибку не снимает, в том числе при записи значения.
- `device.set_error(error)` так же ставит или снимает ошибку самого устройства.
- `control.update_meta(**fields)` меняет поля меты на ходу, например `await control.update_meta(readonly=True)`. Поля те же, что у `create_control`, кроме имени, типа и значения. Чтобы убрать поле из меты, ему передают `None`, например `update_meta(units=None)`, открытая страница веб-интерфейса покажет это только после перезагрузки. Чтобы сменить тип контрола, его пересоздают, `control.remove()` и снова `device.create_control`. Обработчики при этом остаются.
- `device.update_meta(title)` меняет заголовок устройства.
- `control.remove()` удаляет контрол из брокера. Повторный вызов ничего не делает.
- `device.remove()` удаляет из брокера устройство со всеми контролами. Повторный вызов ничего не делает, `control.remove()` после него тоже.
- `client.remove_driver_devices()` находит в брокере все устройства с драйвером этого клиента, удаляет их, включая созданные в этом запуске, и возвращает список их имён. Без связи бросает `BrokerDisconnectedError`.

После `device.remove()` действия над своим устройством и его контролами, `set_value`, `set_error`, `update_meta` и `create_control`, бросают `ControlMissingError`. `on_command` назначить можно, обработчик заработает, когда сервис создаст устройство заново.


## Чужие устройства

```python
relay = await client.get_control("wb-mr6c_10/K1")
await relay.set_value(True)  # команда в /devices/wb-mr6c_10/controls/K1/on
```

| Вызов                                     | Что делает                                                                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `client.get_control(name)`                | подписывается на устройство, ждёт ответа брокера и отдаёт объект контрола, даже если контрола нет                           |
| `client.get_control(name, timeout=60)`    | то же, но ждёт появления контрола до 60 секунд, иначе бросает `TimeoutError`                                                |
| `client.get_device(name, timeout=None)`   | то же для устройства                                                                                                        |

Без `timeout` `get_control` и `get_device` ждут, пока брокер отдаст всё, что хранит по устройству, и возвращают объект, даже если такого контрола в устройстве нет или нет самого устройства. Такой объект приходит с `exists = False`, а `on_added` сработает, когда контрол или устройство появится.

`get_control` и `get_device` подписываются на всё устройство, даже если сервис запросил один контрол. Повторный запрос того же устройства новой подписки не создаёт, подписка живёт до `close()`. Старые подтопики меты вроде `/meta/type` библиотека не читает.

Устройство существует, пока у него есть мета или хоть один контрол с метой. Только что появившееся устройство может быть ещё без контролов, драйвер публикует их следом.

Когда чужой драйвер стирает мету контрола, например при своём перезапуске, обработчики остаются, `exists` становится `False`, `value` равно `None`, а `set_value` бросает `ControlMissingError`. Когда драйвер опубликует контрол снова, объекты снова увидят мету и значение.

Если драйвер что-то стёр, пока у клиента не было связи, библиотека этого не увидит. Удалённое устройство или контрол останется с `exists = True`, а стёртое значение и снятая ошибка останутся прежними. Так будет, пока драйвер снова не опубликует устройство.

`set_value` чужого контрола с `readonly` отправляет команду как обычно, примет ли её драйвер, решает он сам.

Чужое устройство удалить нельзя, `remove()` бросает `NotOwnError`. Стереть чужие топики можно сырыми методами, рецепт в разделе [Работа с MQTT вне конвенции](#работа-с-mqtt-вне-конвенции).


## Поля объектов

### Поля устройства

| Поле       | Что это                                                           |
| ---------- | ----------------------------------------------------------------- |
| `name`     | имя, например «wb-mr6c_10»                                        |
| `controls` | словарь «имя → контрол» из контролов, которые есть сейчас         |
| `exists`   | у устройства есть мета или хоть один контрол                      |
| `is_own`   | устройство создал этот клиент и ещё не удалил                     |
| `title`    | заголовок `TranslatedTitle`                                       |
| `driver`   | имя драйвера из меты                                              |
| `error`    | ошибка самого устройства, `ControlErrorFlags`                     |

### Поля контрола

| Поле                                | Что это                                                                                                   |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `name`                              | имя, например «K1»                                                                                        |
| `full_name`                         | имя с устройством, например «wb-mr6c_10/K1»                                                               |
| `device`                            | объект устройства                                                                                         |
| `exists`                            | у контрола есть мета                                                                                      |
| `is_own`                            | контрол своего устройства                                                                                 |
| `value`                             | значение контрола, по таблице ниже                                                                        |
| `error`                             | ошибка контрола, `ControlErrorFlags`                                                                      |
| `title`                             | заголовок `TranslatedTitle`                                                                               |
| `control_type`, `units`, `readonly` | поля меты                                                                                                 |
| `meta`                              | `ControlMeta` со всеми полями меты, в том числе `precision`, `minimum`, `maximum`, `order`, `hidden` и `enum` |

Без ошибки `error` равен `ControlErrorFlags.NONE`, а он в условии ложен, поэтому пишут `if control.error:`.

`title.ru` и `title.en` это заголовок на каждом языке. `title.get("ru", control.name)` отдаёт заголовок на русском, без него на английском, а если заголовка нет совсем, второй аргумент, здесь имя контрола.

`TranslatedTitle`, `ControlMeta` и `ControlErrorFlags` импортируются из библиотеки, например для аннотаций типов.

### Значения по типам контрола

Значение контрола в Python зависит от его типа. Такое же значение приходит в событиях и командах, и такое же принимает `set_value`.

| Тип контрола                                                    | Значение в Python                                                                               | В топике                          |
| --------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------- |
| `switch`, `alarm`, `wo-switch`                                  | `True` или `False`                                                                              | `1` или `0`                       |
| `value`, `range` и устаревшие числовые типы вроде `temperature` | конечное число, `int` или `float`                                                               | число, округлённое по `precision` |
| `local_time`, `w1-id`                                           | `int`                                                                                           | целое                             |
| `rgb`                                                           | кортеж из трёх целых от 0 до 255, например `(255, 0, 10)`. `set_value` принимает и список       | `255;0;10`                        |
| `text`                                                          | `str`. `set_value` принимает любое значение и приводит его к строке                             | строка                            |
| `pushbutton`                                                    | значения нет, всегда `None`. Нажатие и команда приходят как `True`, `set_value` принимает только `True` | `1` без retained          |
| неизвестный тип чужого контрола                                 | `str` как есть                                                                                  | строка                            |

`set_value` принимает только значения из таблицы. На другое, например `0` вместо `False` или `NaN` вместо числа, он бросает `TypeError` и ничего не публикует. Если строку из брокера не разобрать по типу контрола, значение остаётся строкой. Значение равно `None`, пока контрола нет или пока его мета уже пришла, а значение ещё нет.


## Обработчики событий

Обработчики назначаются на объекты методами `on_*`.

Обработчик может быть обычной или асинхронной функцией. Первым аргументом он получает объект, на котором сработало событие, поэтому одну функцию можно назначить на несколько объектов. Число аргументов библиотека проверяет при назначении и сразу бросает `TypeError`. Методы `on_*` работают и как декораторы.

```python
@sensor.on_value
async def sensor_changed(control: Control, value: Any, previous: Any) -> None: ...
```

### Обработчики контрола

| Метод        | Когда срабатывает                                                                                                                         | Что получает обработчик    |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| `on_added`   | у контрола появилась мета с типом                                                                                                         | `control`                  |
| `on_removed` | мета контрола стёрта                                                                                                                      | `control`                  |
| `on_value`   | значение изменилось, у `pushbutton` каждое нажатие                                                                                        | `control, value, previous` |
| `on_error`   | ошибка изменилась                                                                                                                         | `control, error, previous` |
| `on_meta`    | изменилось поле меты, например заголовок, `readonly` или тип. При смене типа `value` перечитывается по новому типу, а `on_value` не приходит | `control`                  |
| `on_command` | пришла команда в `/on`, только у своего контрола                                                                                          | `control, value`           |

### Обработчики устройства

| Метод                | Когда срабатывает                                                    | Что получает обработчик    |
| -------------------- | -------------------------------------------------------------------- | -------------------------- |
| `on_added`           | у устройства появилась мета или первый контрол с метой               | `device`                   |
| `on_removed`         | пропали и мета устройства, и последний контрол                       | `device`                   |
| `on_meta`            | сменился заголовок или драйвер                                       | `device`                   |
| `on_error`           | изменилась ошибка самого устройства                                  | `device, error, previous`  |
| `on_control_added`   | у устройства появился контрол                                        | `control`                  |
| `on_control_removed` | у устройства пропал контрол                                          | `control`                  |
| `on_control_value`   | изменилось значение любого контрола устройства                       | `control, value, previous` |
| `on_control_error`   | изменилась ошибка любого контрола устройства                         | `control, error, previous` |
| `on_control_meta`    | изменилась мета любого контрола устройства                           | `control`                  |
| `on_control_command` | пришла команда в `/on` любого контрола, только у своего устройства   | `control, value`           |

### Срабатывание обработчиков при назначении

Часть обработчиков при назначении сразу получает текущее состояние, а дальше только изменения.

- `control.on_value` — с текущим значением и `previous=None`, если значение есть.
- `control.on_error` — с текущей ошибкой, если контрол есть.
- `control.on_added` — если контрол есть.
- `device.on_added` — если устройство есть.
- `device.on_error` — с текущей ошибкой устройства, если оно есть.
- `device.on_control_added` — для каждого контрола, который есть.
- `device.on_control_value` — для каждого контрола, у которого есть значение, с `previous=None`.
- `device.on_control_error` — для каждого контрола, который есть, с его текущей ошибкой.

Остальные обработчики при назначении не срабатывают и ждут новых событий.

`previous` это прошлое значение контрола, или `None`, если его не было. Обработчик, которому первый вызов не нужен, например уведомление «дверь открылась», отсеивает его по `previous is None`.

### Команды

Команда приходит в `on_command` значением по типу контрола, по таблице из раздела [Значения по типам контрола](#значения-по-типам-контрола).

- У `switch` любое ненулевое число в `/on` означает `True`, например «2», а ноль `False`.
- Тело, которое не разбирается по типу, приходит строкой как есть, например «abc» в `range`. Поэтому обработчик, который записывает команду в контрол, проверяет тип, иначе `set_value` бросит `TypeError`, а библиотека запишет его в лог как ошибку обработчика.
- Пустое сообщение в `/on` обработчику не приходит.
- Команды не копятся. Если в момент команды у контрола нет обработчика, команда теряется, и назначенный позже обработчик её не получит.
- Сама библиотека значение контрола по команде не меняет, его записывает обработчик через `set_value`.
- Сообщение в `/on` с флагом retain библиотека не исполняет и стирает из брокера.

### Обработчик объявляют один раз

Обработчики живут, пока сервис их не снимет. Пропажа и появление контрола их не трогают. Обработчик чужого контрола продолжает работать, когда перезапускается сервис, который публикует это устройство, а обработчик своего контрола работает и после `remove()`, и после нового создания.

Повторное назначение той же функции на тот же объект ничего не добавляет. Функция, объявленная внутри кода, который выполняется много раз, например при каждом создании устройства или в `on_added`, каждый раз новая и встаёт рядом с прежней. Такой обработчик объявляют один раз снаружи, а данные он берёт по имени объекта.

```python
# Неверно. Если устройство трижды удалили и создали снова,
# одна команда вызовет toggle_command трижды
async def add(connection: Connection) -> None:
    device = await client.create_device(connection.name)
    toggle = await device.create_control("toggle", control_type=ControlType.PUSHBUTTON)

    async def toggle_command(control: Control, value: Any) -> None:
        await connection.toggle()

    toggle.on_command(toggle_command)
```

```python
# Верно. Функция одна, повторное назначение ничего не добавляет
connections: dict[str, Connection] = {}


async def toggle_command(control: Control, value: Any) -> None:
    await connections[control.device.name].toggle()


async def add(connection: Connection) -> None:
    device = await client.create_device(connection.name)
    connections[device.name] = connection
    toggle = await device.create_control("toggle", control_type=ControlType.PUSHBUTTON)
    toggle.on_command(toggle_command)
```

### Обработчик, который пишет в контрол

`on_value` срабатывает на каждое изменение значения, в том числе на запись из самого обработчика. Своё значение меняется сразу при `set_value`, а запись в чужой контрол уходит командой, драйвер её выполняет, и новое значение приходит из брокера. Если обработчик `on_value` каждый раз пишет в тот же контрол новое значение, он вызывает сам себя снова и снова и забивает брокер публикациями. Так же зацикливаются два обработчика, которые пишут в контролы друг друга.

```python
relay = await device.create_control(
    "relay", control_type=ControlType.SWITCH, value=False
)


# Неверно. Каждая запись меняет значение и снова вызывает обработчик
async def toggle_back(control: Control, value: Any, previous: Any) -> None:
    await control.set_value(not value)


relay.on_value(toggle_back)
```

Запись того же значения, что уже стоит в контроле, события не даёт, на ней цикл и кончается. Поэтому обработчик, который поправляет значение, пишет только когда значение нужно поменять.

```python
setpoint = await device.create_control(
    "setpoint", control_type=ControlType.RANGE, value=20, maximum=50, minimum=0
)


# Верно. Записанное 30 придёт в обработчик ещё раз, и он ничего не запишет
async def limit(control: Control, value: Any, previous: Any) -> None:
    if value > 30:
        await control.set_value(30)


setpoint.on_value(limit)
```

### Снятие обработчика

| Вызов                                                               | Что делает                                                                                                                                                                                                                    |
| ------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `control.remove_handler(handler)`, `device.remove_handler(handler)` | без `await`, снимает функцию со всех `on_*` этого объекта, у устройства и с `on_control_*`. Та же функция на других объектах остаётся |
| `client.remove_handler(handler)`                                    | без `await`, снимает функцию с `on_connection_change`                                                                                                                                                                         |
| `await client.raw.unsubscribe(handler)`                             | снимает сырой обработчик со всех его фильтров. Если у фильтра не осталось обработчиков, библиотека отписывается в брокере                                                                                                    |

Снимают ту же функцию, которую назначали, поэтому лямбду, которую потом надо снять, сохраняют в переменную. После снятия обработчик больше не вызывается.


## Порядок событий и фоновые задачи

Каждый обработчик разбирает свои события по одному, в порядке прихода. Следующий вызов начинается, когда закончился предыдущий. Разные обработчики друг друга не ждут, и порядок между ними не задан. Поэтому состояние других контролов обработчик читает из их объектов и не рассчитывает, что другой обработчик уже отработал. Одна функция, назначенная на два объекта или на два события, разбирает их независимо, и её вызовы могут пересечься на `await`.

Если обработчик медленнее потока событий, его события копятся, а когда их наберётся 100, библиотека пишет предупреждение в лог.

Долгую работу, например сканирование шины на минуту, обработчик запускает через `client.start_task(coroutine)` и сразу возвращается. Тогда следующие события, например команда отмены, не ждут конца этой работы. Так же запускают фоновую работу, например периодический опрос. В отличие от `asyncio.create_task`, клиент пишет ошибку такой задачи в лог и отменяет задачу при `close()`.

```python
# Опрос датчика вне MQTT, здесь температуры процессора из файла ядра
CPU_TEMPERATURE = Path("/sys/class/thermal/thermal_zone0/temp")


async def poll_cpu_temperature() -> None:
    while True:
        millidegrees = int(CPU_TEMPERATURE.read_text(encoding="utf-8"))
        await temperature.set_value(millidegrees / 1000)
        await asyncio.sleep(10)


client.start_task(poll_cpu_temperature())
```


## Работа с MQTT вне конвенции

Для топиков вне конвенции есть сырые методы в `client.raw`. Внутри конвенции библиотека публикует с QoS 1 и подписывается с QoS 0, другой QoS задают в сырых методах.

| Вызов                                                           | Что делает                                                                                                                                                                                                         |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `await client.raw.subscribe(topic_filter, handler, qos=0)`      | подписка по фильтру с масками `+` и `#` до `unsubscribe` или `close()`. Возвращается, когда retained-сообщения под фильтром уже стоят в очереди обработчика. После переподключения подписка восстанавливается сама |
| `await client.raw.unsubscribe(handler)`                         | снимает обработчик со всех его фильтров                                                                                                                                                                            |
| `await client.raw.read(topic_filter)`                           | разово отдаёт то, что брокер хранит под фильтром сейчас, словарём «топик → тело» |
| `await client.raw.publish(topic, payload, qos=1, retain=False)` | публикует сообщение. Топик без масок, тело строкой, байтами, числом или `None`, но не `bool`                                                                                                                       |

```python
# Список устройств шлюза приходит при подписке и при каждом изменении
async def devices_changed(message: Message) -> None:
    for device in json.loads(message.payload):
        logger.info("Gateway device %s", device["name"])


await client.raw.subscribe("gateway/devices", devices_changed)
# Разовое чтение, словарь «топик → тело» в байтах
state = await client.raw.read("gateway/state")
online = state.get("gateway/state") == b"online"
# Запрос шлюзу
await client.raw.publish("gateway/request/scan", '{"time": 60}')
```

Обработчик получает `Message` с полями `topic`, `payload` в байтах, `retain` и `qos`. Флаг `retain` такой, с каким сообщение опубликовали. `retain=True` у сохранённых сообщений, которые брокер отдаёт при подписке и после каждого переподключения, и у новых сообщений, опубликованных с флагом retain. `retain=False` у сообщений, опубликованных без него.

Одну функцию можно подписать на несколько фильтров, она разбирает их сообщения по одному, а сообщение, которое подходит под два её фильтра, приходит один раз. Второй обработчик на том же фильтре тоже получает всё, что брокер хранит под фильтром.

Сообщение с `retain=True` брокер хранит и отдаёт каждому новому подписчику. Пустое сообщение с `retain=True` стирает топик.

После каждого переподключения клиент публикует свои retained-сообщения заново, кроме стёртых.

Сообщение без retain получат только те, кто подписан сейчас. Без связи такой `raw.publish` сразу бросает `BrokerDisconnectedError`.

Значения устройств конвенции меняют через объекты. Сырым методом можно послать команду в `/on` своего или чужого контрола, она дойдёт до драйвера или до `on_command` так же, как команда другого сервиса. Запись сырым методом прямо в топик значения библиотека не учитывает, значение в объекте останется прежним.

Отдельного метода удаления нет. Один топик стирается пустым retained, а много топиков по маске стираются так.

```python
for topic in await client.raw.read("/devices/old_device/#"):
    await client.raw.publish(topic, "", retain=True)
```

Обработчик, который ждёт ответ на один запрос, снимают сразу после ответа. Иначе каждый запрос оставлял бы на фильтре ещё одну функцию.

```python
async def scan(client: Client, seconds: int) -> Any:
    answer = asyncio.get_running_loop().create_future()

    async def on_response(message: Message) -> None:
        if not answer.done():
            answer.set_result(json.loads(message.payload))

    await client.raw.subscribe("gateway/response/scan", on_response)
    try:
        await client.raw.publish("gateway/request/scan", json.dumps({"time": seconds}))
        return await asyncio.wait_for(answer, 10)
    finally:
        await client.raw.unsubscribe(on_response)
```


## Ошибки

| Ошибка                    | Когда                                                                                                                                              |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BrokerDisconnectedError` | вызову нужен ответ брокера, а связи нет или брокер не ответил вовремя. Это чтение брокера, в том числе в `create_device` и `get_control`, и сообщения без retain, то есть команды и нажатия |
| `NotOwnError`             | действие, которое можно только со своим устройством, над чужим, например `set_error` или `on_command`                                              |
| `ControlMissingError`     | действие с контролом, которого сейчас нет, или со своим устройством после его `remove()`                                                          |
| `DeviceTakenError`        | `create_device` без `force`, когда имя занято устройством другого драйвера                                                                         |
| `LoginRejectedError`      | брокер отверг логин при первом подключении                                                                                                         |
| `ClientClosedError`       | вызов после `close()` или ожидание брокера, которое прервал `close()`                                                                              |
| `TimeoutError`            | нужное значение, контрол или устройство не появились за `timeout`                                                                                 |
| `ValueError`              | неверное имя, топик, значение поля меты или адрес брокера, устройство или контрол уже созданы, второй клиент с тем же драйвером в процессе         |
| `TypeError`               | значение не подходит к типу контрола, у аргумента не тот тип, неизвестное поле меты, у обработчика не то число аргументов                          |
| `RuntimeError`            | повторный `connect()` подключённого клиента                                                                                                       |

Ошибки библиотеки наследуют `MqttLibError`, а `TimeoutError`, `ValueError`, `TypeError` и `RuntimeError` встроенные в Python. `TypeError` и `RuntimeError` означают ошибку в коде сервиса, ловить их не нужно. `DeviceTakenError` наследует ещё и `ValueError`. Ошибки aiomqtt до сервиса не доходят.

Исключение в обработчике событий библиотека пишет в лог и разбирает следующие события дальше. Вне обработчиков исключение уходит в вызывающий код, как у любой функции.


## Логи

Библиотека пишет в стандартный `logging`, вывод настраивает сервис. Имена логгеров идут по пути импорта, у библиотеки внутри пакета сервиса это `wb.<сервис>.wb_mqtt_lib.client`, `.device_sync`, `.subscriber`, `.publisher`, `.listeners` и `.state`, а строки aiomqtt и paho идут в `wb.<сервис>.wb_mqtt_lib.link.aiomqtt`. Обрыв связи клиент пишет одной строкой WARNING.

Подробности работы библиотеки идут на уровне DEBUG. Включить его только для библиотеки при общем уровне INFO можно так.

```python
logging.basicConfig(level=logging.INFO)
logging.getLogger("wb.mqtt_example.wb_mqtt_lib").setLevel(logging.DEBUG)
```


## Когда нужен await

Без `await` вызывают `on_*`, `remove_handler`, `client.start_task` и читают поля объектов. Остальные методы библиотеки асинхронные, их вызывают через `await`.
