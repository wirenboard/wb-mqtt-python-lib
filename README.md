## Как устроена библиотека

Работа с библиотекой начинается с [клиента](#клиент), это класс `Client`. Сервис создаёт клиента при запуске и подключает его к брокеру MQTT. Пока сервис работает, клиент держит соединение и сам переподключается после обрыва.

По умолчанию клиент подключается к брокеру на контроллере Wiren Board. Подключение идёт через unix-сокет, то есть напрямую, без сети, и пароль для него не нужен. Чтобы подключиться к стороннему брокеру, передайте его адрес при создании клиента.

Сервис создаёт [свои устройства](#свои-устройства) через клиента. Библиотека публикует их в MQTT по [конвенции Wiren Board](https://github.com/wirenboard/conventions), и они появляются в веб-интерфейсе контроллера.

[Чужие устройства](#чужие-устройства) публикуют другие драйверы, например wb-mqtt-serial. Сервис получает через клиента объект такого устройства или его контрола по адресу, например `wb-mr6c_10/K1`. Объект устройства это `Device`, объект контрола `Control`, свои устройства описывают те же классы. Объект можно получить, даже если устройства ещё нет в брокере.

Текущие значения, мету и ошибки сервис читает из полей объекта, а библиотека сама обновляет их по сообщениям из брокера. Если сервис записывает значение в чужой контрол, библиотека отправляет команду в топик `/on`, а выполняет её драйвер устройства. Подробнее в разделе [Свои и чужие устройства](#свои-и-чужие-устройства).

Чтобы реагировать на события, сервис назначает на объекты [обработчики](#обработчики-событий) методами `on_*`. Например, изменение значения контрола получает обработчик `on_value`.

Топики, которые не относятся к конвенции, например топики zigbee2mqtt, сервис читает и пишет [методами `client.raw`](#работа-с-mqtt-вне-конвенции).

## Порядок работы

1. Создайте клиента с именем драйвера сервиса, например `wb-mqtt-example`, и подключитесь к брокеру.
2. Создайте свои устройства и их контролы.
3. Получите чужие устройства и контролы, которые нужны сервису.
4. Назначьте обработчики на изменения устройств и их контролов.
5. Перед отключением удалите свои устройства, если они не должны остаться в веб-интерфейсе.

## Быстрый старт

В примере ниже сервис `wb-mqtt-load-alarm` включает аварию, когда нагрузка на процессор выше порога. Среднюю нагрузку публикует другой сервис, wb-mqtt-metrics. Наш сервис создаёт своё устройство с двумя контролами, порогом и аварией. Порог пользователь меняет в веб-интерфейсе. Библиотека подключена к сервису так, как описано в разделе [Подключение к сервису](#подключение-к-сервису).

```python
import asyncio
import contextlib
import logging
import signal
from typing import Any

from wb.mqtt_load_alarm.wb_mqtt_lib import (
    BrokerDisconnectedError,
    Client,
    Control,
    ControlType,
)

THRESHOLD_MIN = 0
THRESHOLD_MAX = 10


async def run() -> None:
    # Вход в async with ждёт подключения к брокеру,
    # сигнал остановки прерывает и это ожидание
    async with Client(driver="wb-mqtt-load-alarm") as client:
        try:
            # Своё устройство, оно появится в веб-интерфейсе
            device = await client.create_device(
                "load_alarm", title={"en": "Load Alarm", "ru": "Нагрузка"}
            )
            threshold = await device.create_control(
                "threshold",
                control_type=ControlType.RANGE,
                title={"en": "Threshold", "ru": "Порог"},
                value=2,
                maximum=THRESHOLD_MAX,
                minimum=THRESHOLD_MIN,
            )
            alarm = await device.create_control(
                "alarm",
                control_type=ControlType.ALARM,
                title={"en": "High Load", "ru": "Высокая нагрузка"},
                value=False,
                readonly=True,
            )
            # Контрол другого сервиса, его публикует wb-mqtt-metrics
            load = await client.get_control("metrics/load_average_1min")

            # Пользователь поменял порог в веб-интерфейсе
            async def threshold_command(control: Control, value: Any) -> None:
                is_number = isinstance(value, (int, float))
                if is_number and THRESHOLD_MIN <= value <= THRESHOLD_MAX:
                    await control.set_value(value)

            # Поменялась нагрузка или порог
            async def update_alarm(control: Control, value: Any, previous: Any) -> None:
                if load.value is not None:
                    await alarm.set_value(load.value > threshold.value)

            threshold.on_command(threshold_command)
            load.on_value(update_alarm)
            threshold.on_value(update_alarm)

            # Вариант с декораторами. Функция назначается при объявлении,
            # и три строки выше не нужны
            # @threshold.on_command
            # async def threshold_command(control: Control, value: Any) -> None:
            #     ...
            #
            # @load.on_value
            # @threshold.on_value
            # async def update_alarm(
            #     control: Control, value: Any, previous: Any
            # ) -> None:
            #     ...

            # Сервис работает, пока его не остановят сигналом
            await asyncio.Future()
        finally:
            # Перед выходом сервис стирает своё устройство,
            # чтобы оно не осталось в веб-интерфейсе
            with contextlib.suppress(BrokerDisconnectedError):
                await client.remove_driver_devices()


async def main() -> None:
    # SIGTERM от systemd и Ctrl+C отменяют главную задачу,
    # и сервис выходит через finally
    task = asyncio.current_task()
    loop = asyncio.get_running_loop()
    for signal_number in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(signal_number, task.cancel)
    with contextlib.suppress(asyncio.CancelledError):
        await run()


if __name__ == "__main__":
    logging.basicConfig(level=logging.INFO)
    asyncio.run(main())
```

- `create_device` и `create_control` публикуют устройство сервиса и его контролы. Если в брокере осталось устройство сервиса с прошлого запуска, библиотека сначала стирает его.
- `get_control` возвращает объект контрола, даже если wb-mqtt-metrics ещё не запущен. Значение в объекте появится, когда wb-mqtt-metrics его опубликует.
- Если у контрола уже есть значение, `on_value` вызывает обработчик сразу при назначении, а потом на каждое изменение. Поэтому при запуске сервису не нужно отдельно читать значения. Функция `update_alarm` назначена и на нагрузку, и на порог, и авария пересчитывается, когда меняется любой из них.
- Когда пользователь меняет порог в веб-интерфейсе, библиотека вызывает `threshold_command` с новым значением. Сама библиотека значение порога не меняет, его записывает обработчик через `set_value`. Команду может прислать и правило или другой сервис, причём с любым значением. Поэтому перед записью обработчик проверяет, что пришло число в допустимых пределах.
- systemd останавливает сервис сигналом SIGTERM. Если сервис не обрабатывает этот сигнал, Python завершается сразу и не доходит до `finally`. Поэтому `main` ставит свой обработчик сигнала. Он отменяет главную задачу, и `await asyncio.Future()` прерывается. Затем `finally` стирает устройство, а выход из `async with` закрывает клиент.

## Подключение к сервису

Библиотека работает на Python 3.13 с [aiomqtt](https://github.com/empicano/aiomqtt) 2.x и на контроллерах Wiren Board с Debian trixie.

Добавьте библиотеку git-сабмодулем в корень репозитория сервиса. При установке сервиса она попадёт внутрь его пакета, например в `wb.mqtt_example.wb_mqtt_lib`.

```bash
# Добавить библиотеку сабмодулем
git submodule add https://github.com/wirenboard/wb-mqtt-python-lib.git wb-mqtt-python-lib
# Закрепить нужную версию библиотеки
git -C wb-mqtt-python-lib checkout <коммит>
# В коммит сервиса попадает файл .gitmodules и хэш сабмодуля
git add .gitmodules wb-mqtt-python-lib
```

В `setup.py` сервиса добавьте пакет библиотеки и его подпакеты к пакетам сервиса.

```python
from setuptools import find_namespace_packages, find_packages, setup

LIB_PACKAGE = "wb.mqtt_example.wb_mqtt_lib"
LIB_DIR = "wb-mqtt-python-lib/wb_mqtt_lib"

setup(
    name="wb-mqtt-example",
    packages=find_namespace_packages(include=["wb.*"])
    + [LIB_PACKAGE]
    + [f"{LIB_PACKAGE}.{name}" for name in find_packages(LIB_DIR)],
    package_dir={LIB_PACKAGE: LIB_DIR},
)
```

Сервис импортирует библиотеку из своего пакета.

```python
from wb.mqtt_example.wb_mqtt_lib import Client, ControlType
```

Что ещё нужно в репозитории сервиса:

- Добавьте `python3-asyncio-mqtt (>= 2.3.1)` в `Depends` в `debian/control`. Сабмодуль сам свои зависимости не приносит. Если тесты сервиса при сборке импортируют библиотеку, добавьте этот пакет и в `Build-Depends`.
- Клонируйте репозиторий сервиса с `--recurse-submodules` или после клонирования выполните `git submodule update --init`.

Новая версия библиотеки попадает в сервис, только когда вы обновите сабмодуль.

```bash
# Забрать новые коммиты библиотеки
git -C wb-mqtt-python-lib fetch
# Перейти на нужный коммит
git -C wb-mqtt-python-lib checkout <коммит>
# В PR сервиса будет видна только смена хэша
git add wb-mqtt-python-lib
```

## Клиент

```python
Client(driver: str, broker_url: str = DEFAULT_BROKER_URL)
```

`driver` задаёт имя драйвера сервиса, например `wb-mqtt-example`. Библиотека записывает его в мету каждого устройства сервиса. По этому имени она находит устройства сервиса, в том числе оставшиеся от прошлого запуска.

По умолчанию `broker_url` равен `unix:///var/run/mosquitto/mosquitto.sock`. Это unix-сокет брокера на контроллере, через него пароль не нужен. Если брокер работает на другой машине или нужен тестовый брокер, адрес пишется так:

- `tcp://host:port` и `mqtt-tcp://host:port`, обе записи работают одинаково.
- `ws://host:port/path`, подключение через websocket. `path` это путь websocket на сервере брокера. Если его не указать, клиент подключается по пути `/mqtt`.
- `unix:///path/to/socket`, путь к сокету после трёх косых черт.
- Логин и пароль пишутся перед хостом, `tcp://user:password@host:1883`. Символы `/`, `?`, `#`, `@`, `:` и `%` в них кодируются процентами, например `%2F` вместо `/`.

Если адрес неверный, `Client` сразу бросает `ValueError`. Клиент работает по MQTT 5, поэтому другой брокер тоже должен его поддерживать. Соединения `tcp://` и `ws://` не шифруются, логин и пароль передаются по сети открытым текстом.

При входе в `async with` клиент ждёт первого соединения и повторяет попытки, пока брокер не ответит. Чтобы ограничить время ожидания, подключите клиента через `connect()` с таймаутом. После `TimeoutError` клиент в фоне не переподключается.

```python
client = Client(driver="wb-mqtt-example")
try:
    # Ждать брокер не дольше 30 с
    await asyncio.wait_for(client.connect(), timeout=30)
except TimeoutError:
    logger.error("MQTT broker is not available")
    return
```

Если при первом подключении брокер отверг логин или пароль, подключение бросает `LoginRejectedError`, и клиент больше не пытается подключиться. После первого успешного соединения клиент переподключается сам после любого обрыва, даже если брокер начал отвергать логин. Пауза между попытками растёт от 0,5 до 30 с.

Сервису достаточно одного клиента. Второй нужен, только если часть устройств сервис публикует под другим именем драйвера. Клиент считает своими все устройства своего драйвера, поэтому два клиента с одним именем драйвера могут стереть устройства друг друга. В одном процессе второй клиент с тем же именем, пока первый не закрыт, при подключении получит `ValueError`.

`client.is_connected` показывает, есть ли связь с брокером в текущий момент. Потерю связи обрабатывайте через ошибку `BrokerDisconnectedError`, потому что связь может пропасть сразу после проверки `is_connected`. Без связи команда чужому контролу не ждёт переподключения и сразу бросает эту ошибку. Изменения своих устройств и retained-публикации через `client.raw` без связи ошибку не бросают, библиотека отправит их после переподключения.

`client.on_connection_change(handler)` назначает обработчик, который узнаёт о пропаже и возврате связи. Это единственный обработчик самого клиента. Свои устройства и подписки библиотека восстанавливает сама. Обработчик нужен, только если сервис сам что-то делает при обрыве.

```python
async def link_changed(connected: bool) -> None:
    if connected:
        await bridge.request_state()
    else:
        await bridge.mark_unavailable()


client.on_connection_change(link_changed)
```

- `True` приходит после каждого подключения, когда клиент уже восстановил подписки. Обработчик, назначенный до `connect()` или до запуска цикла событий, получит `True` при первом подключении.
- `False` приходит один раз на обрыв, даже если потом было несколько неудачных попыток переподключиться.
- До первого подключения и при `close()` события нет.
- При назначении обработчик не вызывается. Текущее состояние связи показывает `client.is_connected`.

Клиент закрывается при выходе из `async with` или по `close()`. Он отменяет свои обработчики и фоновые задачи и закрывает соединение. Вызовы, которые в этот момент ждут ответа брокера, бросают `ClientClosedError`, а изменения, которые не успели дойти до брокера, теряются. Закрытый клиент подключить снова нельзя. Для нового соединения создайте новый `Client`, он начинает без устройств, подписок и обработчиков.

Устройства сервиса после закрытия клиента остаются в брокере. Чтобы удалить их, вызовите `remove_driver_devices()` перед выходом, как в [быстром старте](#быстрый-старт).

Если у сервиса свой жизненный цикл, например объект с методами `start` и `stop` или фикстура в тестах, можно обойтись без `async with` и явно вызывать `connect()` и `close()`.

```python
class Service:
    def __init__(self, broker_url: str) -> None:
        self._client = Client(driver="wb-mqtt-example", broker_url=broker_url)

    async def start(self) -> None:
        await self._client.connect()
        device = await self._client.create_device("example", title="Example")
        relay = await device.create_control(
            "relay", control_type=ControlType.SWITCH, value=False
        )
        relay.on_command(self._relay_command)

    async def stop(self) -> None:
        with contextlib.suppress(BrokerDisconnectedError):
            await self._client.remove_driver_devices()
        await self._client.close()

    async def _relay_command(self, control: Control, value: Any) -> None:
        if isinstance(value, bool):
            await control.set_value(value)


async def main() -> None:
    task = asyncio.current_task()
    loop = asyncio.get_running_loop()
    for signal_number in (signal.SIGTERM, signal.SIGINT):
        loop.add_signal_handler(signal_number, task.cancel)
    service = Service(DEFAULT_BROKER_URL)
    with contextlib.suppress(asyncio.CancelledError):
        try:
            await service.start()
            await asyncio.Future()
        finally:
            await service.stop()
```

`stop()` стоит в `finally`, поэтому клиент закроется, даже если `start()` упал на середине. Если сервис остановили сигналом SIGTERM или SIGINT, обработчик сигнала из `main` отменяет главную задачу, как в [быстром старте](#быстрый-старт), и `finally` тоже вызывает `stop()`. Клиент можно создать и до запуска цикла событий, к брокеру он подключается только в `connect()`.

## Свои и чужие устройства

Свои и чужие устройства описывают одни и те же классы `Device` и `Control`. Сервис может получить несколько объектов одного устройства или контрола. Все они показывают одни и те же значения и равны по `==`. Сравнивать их через `is` нельзя, это разные объекты. Получать объект заново не нужно. Он продолжает работать после перезапуска сервиса, который публикует устройство, и после переподключения клиента.

|                                                        | Своё                                                                                  | Чужое                                                                                                                                               |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Откуда состояние                                       | из кода сервиса, библиотека его публикует                                             | из брокера                                                                                                                                          |
| `control.set_value(value)`                             | значение в объекте меняется сразу. В MQTT оно уходит, если изменилась строка в топике | команда уходит в топик `/on`. Значение в объекте изменится, когда драйвер опубликует новое                                                          |
| `set_error`, `update_meta`, `remove`, `create_control` | публикуют и стирают топики                                                            | бросают `NotOwnError`                                                                                                                               |
| `on_command`, `on_control_command`                     | получают команды из `/on`                                                             | бросают `NotOwnError`                                                                                                                               |
| Когда приходят события                                 | в момент вызова в коде сервиса                                                        | когда из брокера пришло сообщение драйвера                                                                                                          |
| После переподключения                                  | библиотека публикует устройство заново                                                | обработчики получают изменения за время обрыва. Что драйвер стёр за время обрыва, библиотека не видит, раздел [Чужие устройства](#чужие-устройства) |
| Устройство изменили в обход библиотеки                 | объекты этого не видят                                                                | обработчики получают изменение                                                                                                                      |

Библиотека не следит за своими устройствами в брокере. Если своё устройство удалили в веб-интерфейсе или кто-то записал значение прямо в топик, объекты не меняются и событий нет.

Объекты устройств и контролов сервис получает через методы `create_device`, `create_control`, `get_device`, `get_control` и поле `device.controls`, а ещё в аргументах обработчиков. Классы `Device` и `Control` нужны сервису только для аннотаций типов.

### Ожидание значения

`await control.wait_value(expected, timeout)` ждёт, пока значение контрола станет равным `expected`. Вместо значения можно передать функцию, тогда метод ждёт, пока она вернёт `True`. Если значение уже подходит, метод возвращается сразу. Если за `timeout` секунд подходящее значение не пришло, он бросает `TimeoutError`. `wait_value` можно вызывать и из обработчика. Если значение стёрли или контрол пропал, метод ждёт дальше до `timeout`.

Чтобы дождаться выполнения своей команды, запускайте ожидание вместе с ней, как в примере ниже. Если вызвать `wait_value` после `set_value`, значение могут успеть изменить ещё раз, и ответ драйвера будет пропущен.

```python
relay = await client.get_control("wb-mr6c_10/K1", timeout=5)
# Ожидание запускается раньше команды, поэтому ответ драйвера не потеряется
await asyncio.gather(relay.wait_value(True, timeout=5), relay.set_value(True))
```

## Свои устройства

```python
device = await client.create_device(
    "waterius_1", title={"en": "Waterius 1", "ru": "Ватериус 1"}
)
cold = await device.create_control(
    "cold_water",
    control_type=ControlType.VALUE,
    title={"en": "Cold Water", "ru": "Холодная вода"},
    value=0.0,
    precision=0.001,
    readonly=True,
    units="m^3",
)
await cold.set_value(12.3456)  # уйдёт как «12.346»
```

### Создание устройства

`client.create_device(name, title=None, force=False)` сначала проверяет, чьи топики уже есть в брокере под этим именем. Если это топики своего драйвера, например от прошлого запуска с другим набором контролов, библиотека их стирает. Затем она публикует мету устройства с заголовком и именем драйвера клиента. Контролы появятся, когда сервис их создаст.

Если под этим именем есть устройство другого драйвера или устройство без драйвера, `create_device` бросает `DeviceTakenError` и ничего не трогает. Если под именем лежат только топики без меты, например одни значения, библиотека считает их остатками и стирает.

С `force=True` библиотека стирает под этим именем всё, в том числе чужое, и публикует своё устройство. Это нужно, например, после смены имени драйвера или когда старая версия сервиса оставила под этим именем устройство без драйвера. Если другой драйвер ещё работает, он продолжит публиковать туда свои значения.

Без связи `create_device` бросает `BrokerDisconnectedError`. Если устройство уже создано, повторный вызов бросает `AlreadyCreatedError`.

### Создание контрола

`device.create_control(name, control_type, ...)` публикует мету контрола и начальное значение, если оно передано. Библиотека проверяет все аргументы до публикации. Если в любом из них ошибка, в брокер ничего не уходит.

Обязательные аргументы:

- `name` — имя контрола. Пустое имя, имя с `/`, `+`, `#` или управляющими символами и слишком длинное имя дают `InvalidNameError`. Для имени устройства в `create_device` правила те же.
- `control_type` — тип контрола из `ControlType`.

Необязательные аргументы:

- `title` — заголовок. Строку веб-интерфейс показывает на любом языке, для двух языков передайте `{"en": "...", "ru": "..."}`.
- `value` — начальное значение, у `pushbutton` его нет.
- `maximum`, `minimum` — пределы для `range` и `value`, конечные числа.
- `precision` — шаг значения, положительное число.
- `readonly` — `True`, если контрол нельзя менять. Команды в его `/on` до обработчиков не доходят.
- `units` — единицы измерения для `value` и `range`.
- `order` — место на карточке устройства, целое число. По умолчанию задаётся в порядке создания.
- `hidden` — `True`, чтобы спрятать контрол в веб-интерфейсе.
- `enum` — названия значений, `{"0": {"en": "Idle", "ru": "Ожидание"}, "1": ...}`.

Поля меты, которые не относятся к типу контрола, библиотека записывает как есть. На значение они не влияют.

В `ControlType` есть десять действующих типов конвенции. Это `SWITCH`, `WO_SWITCH`, `ALARM`, `PUSHBUTTON`, `RANGE`, `RGB`, `TEXT`, `LOCAL_TIME`, `W1_ID` и `VALUE`. Устаревшие типы вроде `temperature` создать нельзя, вместо них конвенция рекомендует `value` с `units`.

### Значения

`control.set_value(value)` проверяет значение по типу контрола. Какие значения принимает каждый тип, показано в разделе [Значения по типам контрола](#значения-по-типам-контрола). Новое значение своего контрола сразу попадает в `control.value` и в события. В MQTT оно уходит, только если изменилась строка в топике. Нажатие `pushbutton` публикуется каждый раз. Для чужого контрола `set_value` отправляет команду в `/on`.

Число с `precision` публикуется с тем же числом знаков после запятой, что и у `precision`, без нулей в конце. Например, при `precision=0.1` значение 21.54 уходит как «21.5», а `control.value` и событие получают 21.54.

### Публикация ошибок

- `control.set_error(error)` ставит или снимает ошибку контрола. Ошибка задаётся флагами `ControlErrorFlags.READ`, `WRITE` и `POLL`, несколько флагов объединяются через `|`. `ControlErrorFlags.NONE` снимает ошибку. Сама библиотека ошибку не снимает, даже при записи значения.
- `device.set_error(error)` так же ставит или снимает ошибку самого устройства.

### Обновление меты

- `control.update_meta(**fields)` меняет поля меты на ходу, например `await control.update_meta(readonly=True)`. Поля те же, что у `create_control`, кроме имени, типа и значения. Чтобы убрать поле из меты, передайте ему `None`, например `update_meta(units=None)`. Чтобы сменить тип контрола, удалите его через `control.remove()` и создайте заново через `device.create_control`. Обработчики при этом сохраняются.
- `device.update_meta(title)` меняет мету устройства. У устройства в мете можно поменять только заголовок.

### Удаление устройств и контролов

- `control.remove()` удаляет контрол из брокера.
- `device.remove()` удаляет из брокера устройство со всеми контролами.
- `client.remove_driver_devices()` находит в брокере все устройства с драйвером этого клиента, удаляет их и возвращает список их имён. Без связи бросает `BrokerDisconnectedError`.

## Чужие устройства

```python
relay = await client.get_control("wb-mr6c_10/K1")
await relay.set_value(True)  # команда в /devices/wb-mr6c_10/controls/K1/on
```

| Вызов                                     | Что делает                                                                   |
| ----------------------------------------- | ---------------------------------------------------------------------------- |
| `client.get_control(address)`             | возвращает объект контрола                                                   |
| `client.get_control(address, timeout=60)` | то же, но ждёт появления контрола до 60 секунд, иначе бросает `TimeoutError` |
| `client.get_device(name, timeout=None)`   | то же для устройства                                                         |

Без `timeout` методы `get_control` и `get_device` ждут, пока брокер пришлёт всё, что хранит по устройству. Объект они возвращают, даже если такого контрола или самого устройства нет. У такого объекта `exists = False`, а обработчик `on_added` сработает, когда контрол или устройство появится.

`get_control` и `get_device` подписываются на всё устройство, даже если сервис запросил один контрол. Повторный запрос того же устройства новую подписку не создаёт. Подписка действует до закрытия клиента.

Устройство считается существующим, пока у него есть мета или хотя бы один контрол с метой. Если чужой драйвер стёр мету контрола, например при своём перезапуске, `exists` становится `False`, `value` становится `None`, а `set_value` бросает `ControlMissingError`. Обработчики остаются, и когда драйвер снова опубликует контрол, объекты увидят его мету и значение. Что драйвер стёр, пока у клиента не было связи, библиотека не видит, и объекты показывают прежнее состояние, пока драйвер снова не опубликует устройство.

`set_value` для чужого контрола с `readonly` ничего не отправляет и бросает `ReadonlyControlError`.

### Поля устройства

| Поле       | Что это                                                                                                                             |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `name`     | имя, например «wb-mr6c_10»                                                                                                          |
| `controls` | словарь «имя → контрол» из контролов, которые есть сейчас                                                                           |

### Поля контрола

| Поле        | Что это                                                                                                                                                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `name`      | имя, например «K1»                                                                                                                                                                                                                                                                               |
| `full_name` | имя с устройством, например «wb-mr6c_10/K1»                                                                                                                                                                                                                                                      |
| `device`    | объект устройства                                                                                                                                                                                                                                                                                |
| `exists`    | у контрола есть мета                                                                                                                                                                                                                                                                             |
| `is_own`    | контрол своего устройства                                                                                                                                                                                                                                                                        |
| `value`     | значение контрола, по таблице ниже                                                                                                                                                                                                                                                               |
| `error`     | ошибка контрола, `ControlErrorFlags`                                                                                                                                                                                                                                                             |
| `meta`      | `ControlMeta` со всеми полями меты, это `control_type`, `title`, `units`, `precision`, `minimum`, `maximum`, `order`, `readonly`, `hidden` и `enum`. Если ошибки нет, `error` равен `ControlErrorFlags.NONE`. В условии это значение ложно, поэтому для проверки достаточно `if control.error:`.

`device.meta.title` и `control.meta.title` хранят переводы заголовка по ключам, `title.en` и `title.ru`. Заголовок, заданный одной строкой, лежит в `title.en`.

`TranslatedTitle`, `DeviceMeta`, `ControlMeta` и `ControlErrorFlags` импортируются из библиотеки, например для аннотаций типов.

### Значения по типам контрола

Значение контрола в Python зависит от его типа. Такое же значение приходит в событиях и командах, и такое же принимает `set_value`.

| Тип контрола                                                    | Значение в Python                                                                                       | В топике                          |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------- |
| `switch`, `alarm`, `wo-switch`                                  | `True` или `False`                                                                                      | `1` или `0`                       |
| `value`, `range` и устаревшие числовые типы вроде `temperature` | конечное число, `int` или `float`                                                                       | число, округлённое по `precision` |
| `local_time`, `w1-id`                                           | `int`                                                                                                   | целое                             |
| `rgb`                                                           | кортеж из трёх целых от 0 до 255, например `(255, 0, 10)`. `set_value` принимает и список               | `255;0;10`                        |
| `text`                                                          | `str`. `set_value` принимает только строку. Пустая строка считывается из брокера как `None`             | строка                            |
| `pushbutton`                                                    | значения нет, всегда `None`. Нажатие и команда приходят как `True`, `set_value` принимает только `True` | `1` без retained                  |
| неизвестный тип чужого контрола                                 | `str` как есть                                                                                          | строка                            |

`set_value` принимает только значения из таблицы. На другое значение, например `0` вместо `False` или `NaN` вместо числа, он бросает `TypeError` и ничего не публикует. Если строку из брокера не получается разобрать по типу контрола, значение остаётся строкой. Значение равно `None`, если значения нет или мета контрола не опубликована.

## Обработчики событий

Обработчики назначаются на объекты методами `on_*` без `await`, эти методы работают и как декораторы. Обработчик может быть обычной или асинхронной функцией.

```python
@sensor.on_value
async def sensor_changed(control: Control, value: Any, previous: Any) -> None: ...
```

Одну функцию можно назначить на несколько объектов. Число аргументов библиотека проверяет при назначении. Если оно не подходит, `on_*` сразу бросает `TypeError`. Назначенный обработчик работает, пока сервис его не снимет. Он остаётся, даже если контрол пропал или сервис удалил своё устройство через `remove()`, и снова работает, когда контрол появится.

Объявляйте функцию-обработчик один раз, на уровне модуля или класса, и назначайте её на объекты там, где они создаются. Повторное назначение той же функции на тот же объект ничего не меняет. Функция, объявленная внутри другой функции, создаётся заново при каждом вызове внешней, и обработчиков становится всё больше.

Например, функция `add` создаёт устройство и назначает на его кнопку обработчик `toggle_command`, объявленный внутри `add`. Сервис вызывает `add` при каждом подключении прибора, а при отключении удаляет устройство в функции `remove`. Обработчики после удаления остаются, поэтому после трёх подключений одна команда вызовет `toggle_command` три раза.

```python
# Неверно. После трёх вызовов add одна команда вызовет toggle_command три раза
async def add(connection: Connection) -> None:
    device = await client.create_device(connection.name)
    toggle = await device.create_control("toggle", control_type=ControlType.PUSHBUTTON)

    async def toggle_command(control: Control, value: Any) -> None:
        await connection.toggle()

    toggle.on_command(toggle_command)


async def remove(connection: Connection) -> None:
    device = await client.get_device(connection.name)
    await device.remove()
```

В верном варианте `toggle_command` объявлена вне `add`, а подключение прибора она берёт из словаря по имени устройства.

```python
# Верно. Функция одна, повторное назначение ничего не добавляет
connections: dict[str, Connection] = {}


async def toggle_command(control: Control, value: Any) -> None:
    await connections[control.device.name].toggle()


async def add(connection: Connection) -> None:
    device = await client.create_device(connection.name)
    connections[device.name] = connection
    toggle = await device.create_control("toggle", control_type=ControlType.PUSHBUTTON)
    toggle.on_command(toggle_command)
```

### Обработчики контрола

| Метод        | Когда срабатывает                                                                                                                            | Что получает обработчик    |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------- |
| `on_added`   | у контрола появилась мета с типом                                                                                                            | `control`                  |
| `on_removed` | мета контрола стёрта                                                                                                                         | `control`                  |
| `on_value`   | значение изменилось, у `pushbutton` каждое нажатие                                                                                           | `control, value, previous` |
| `on_error`   | ошибка изменилась                                                                                                                            | `control, error, previous` |
| `on_meta`    | изменилось поле меты, например заголовок, `readonly` или тип. При смене типа `value` перечитывается по новому типу, а `on_value` не приходит | `control`                  |
| `on_command` | пришла команда в `/on`, только у своего контрола без `readonly`                                                                              | `control, value`           |

### Обработчики устройства

| Метод                | Когда срабатывает                                                                 | Что получает обработчик    |
| -------------------- | --------------------------------------------------------------------------------- | -------------------------- |
| `on_added`           | у устройства появилась мета или первый контрол с метой                            | `device`                   |
| `on_removed`         | пропали и мета устройства, и последний контрол                                    | `device`                   |
| `on_meta`            | сменился заголовок или драйвер                                                    | `device`                   |
| `on_error`           | изменилась ошибка самого устройства                                               | `device, error, previous`  |
| `on_control_added`   | у устройства появился контрол                                                     | `control`                  |
| `on_control_removed` | у устройства пропал контрол                                                       | `control`                  |
| `on_control_value`   | изменилось значение любого контрола устройства                                    | `control, value, previous` |
| `on_control_error`   | изменилась ошибка любого контрола устройства                                      | `control, error, previous` |
| `on_control_meta`    | изменилась мета любого контрола устройства                                        | `control`                  |
| `on_control_command` | пришла команда в `/on` любого контрола без `readonly`, только у своего устройства | `control, value`           |

### Срабатывание обработчиков при назначении

Некоторые обработчики при назначении сразу получают текущее состояние, а дальше только изменения.

- `control.on_value` — с текущим значением и `previous=None`, если значение есть.
- `control.on_error` — с текущей ошибкой, если контрол есть.
- `control.on_added` — если контрол есть.
- `device.on_added` — если устройство есть.
- `device.on_error` — с текущей ошибкой устройства, если оно есть.
- `device.on_control_added` — для каждого контрола, который есть.
- `device.on_control_value` — для каждого контрола, у которого есть значение, с `previous=None`.
- `device.on_control_error` — для каждого контрола, который есть, с его текущей ошибкой.

Остальные обработчики при назначении не срабатывают и ждут новых событий.

`previous` содержит прошлое значение контрола или `None`, если значения не было. Если первый вызов обработчику не нужен, например для уведомления «дверь открылась», его можно пропустить по условию `previous is None`. Не подходит для обработчиков контролов с типом `pushbutton`, у них `previous` всегда равен `None`.

### Команды

Команда приходит в `on_command` уже разобранной по типу контрола, как в таблице из раздела [Значения по типам контрола](#значения-по-типам-контрола).

- У `switch` любое ненулевое число в `/on` означает `True`, например «2», а ноль означает `False`.
- Если команду не удаётся разобрать по типу, она приходит строкой как есть, например «abc» для `range`. Поэтому обработчик, который записывает команду в контрол, должен проверить тип. Иначе `set_value` бросит `TypeError`, и библиотека запишет его в лог как ошибку обработчика.
- Пустое сообщение в `/on` обработчику не приходит.
- Команды не копятся. Если в момент команды у контрола нет обработчика, команда теряется, и назначенный позже обработчик её не получит.
- Сама библиотека значение контрола по команде не меняет, его записывает обработчик через `set_value`.
- Сообщение в `/on` с флагом retain библиотека не исполняет и стирает из брокера.

### Снятие обработчика

| Вызов                                                               | Что делает                                                                                                                                  |
| ------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `control.remove_handler(handler)`, `device.remove_handler(handler)` | без `await`, снимает функцию со всех `on_*` этого объекта, а у устройства ещё и с `on_control_*`. Та же функция на других объектах остаётся |
| `client.remove_handler(handler)`                                    | без `await`, снимает функцию с `on_connection_change`                                                                                       |
| `await client.raw.unsubscribe(handler)`                             | снимает обработчик со всех его фильтров. Если у фильтра не осталось обработчиков, библиотека отписывается в брокере                         |

Снять можно только ту же функцию, которую назначили. Поэтому лямбду, которую потом нужно снять, сохраните в переменную. После снятия обработчик больше не вызывается.

## Порядок событий и фоновые задачи

Каждый обработчик получает свои события по одному, в порядке прихода. Следующий вызов начинается, когда закончился предыдущий. Разные обработчики друг друга не ждут, и порядок между ними не определён. Если обработчик не успевает за событиями, они копятся в очереди. Когда в очереди наберётся 100 событий, библиотека пишет предупреждение в лог.

Долгую работу, например сканирование шины в течение минуты, запускайте внутри обработчика через `client.start_task(coroutine)` без `await`. Тогда следующие события не будут ждать конца этой работы. Через `client.start_task` запускайте и фоновую работу, например периодический опрос.

`client.start_task` вместо `asyncio.create_task` нужен потому, что клиент берёт задачу под свой контроль:

- Клиент хранит ссылку на задачу. Задачу из `asyncio.create_task`, на которую никто не ссылается, Python может удалить посреди работы.
- Если задача упала, клиент сразу пишет её ошибку в лог.
- При `close()` клиент отменяет все такие задачи, и сервису не нужно следить за ними самому.

```python
# Опрос датчика вне MQTT, например температуры процессора из файла ядра
CPU_TEMPERATURE = Path("/sys/class/thermal/thermal_zone0/temp")


async def poll_cpu_temperature() -> None:
    while True:
        millidegrees = int(CPU_TEMPERATURE.read_text(encoding="utf-8"))
        await temperature.set_value(millidegrees / 1000)
        await asyncio.sleep(10)


client.start_task(poll_cpu_temperature())
```

## Работа с MQTT вне конвенции

Для топиков вне конвенции есть методы `client.raw`. По умолчанию библиотека публикует с QoS 1 и подписывается с QoS 0. Другой QoS можно задать в методах `client.raw`.

| Вызов                                                           | Что делает                                                                                                                                                                                                                                        |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `await client.raw.subscribe(topic_filter, handler, qos=0)`      | подписывает обработчик на фильтр с масками `+` и `#`. Подписка действует до `unsubscribe` или `close()` и сама восстанавливается после переподключения. Метод возвращается, когда retained-сообщения под фильтром уже стоят в очереди обработчика |
| `await client.raw.unsubscribe(handler)`                         | снимает обработчик со всех его фильтров                                                                                                                                                                                                           |
| `await client.raw.read(topic_filter)`                           | разово возвращает то, что брокер хранит под фильтром сейчас, словарём «топик → тело»                                                                                                                                                              |
| `await client.raw.publish(topic, payload, qos=1, retain=False)` | публикует сообщение. Топик без масок, тело строкой, байтами, числом или `None`, но не `bool`                                                                                                                                                      |

```python
# Список устройств шлюза приходит при подписке и при каждом изменении
async def devices_changed(message: Message) -> None:
    for device in json.loads(message.payload):
        logger.info("Gateway device %s", device["name"])


await client.raw.subscribe("gateway/devices", devices_changed)
# Разовое чтение, словарь «топик → тело» в байтах
state = await client.raw.read("gateway/state")
online = state.get("gateway/state") == b"online"
# Запрос шлюзу
await client.raw.publish("gateway/request/scan", '{"time": 60}')
```

Обработчик получает `Message` с полями `topic`, `payload` в байтах, `retain` и `qos`. Флаг `retain` совпадает с тем, с каким сообщение опубликовали. Он равен `True` у сохранённых сообщений, которые брокер присылает при подписке и после каждого переподключения, и у новых сообщений, опубликованных с retain. У сообщений без retain он равен `False`.

Одну функцию можно подписать на несколько фильтров. Она получает их сообщения по одному, а сообщение, которое подходит под два её фильтра, приходит один раз. Если на тот же фильтр подписать второй обработчик, он тоже получит всё, что брокер хранит под этим фильтром.

Сообщение с `retain=True` брокер хранит и отдаёт каждому новому подписчику, а после переподключения клиент публикует свои retained-сообщения заново, кроме стёртых. Сообщение без retain получат только те, кто подписан в момент публикации, и без связи `raw.publish` такого сообщения сразу бросает `BrokerDisconnectedError`.

Значения устройств по конвенции меняйте через объекты. Через `client.raw` можно отправить команду в `/on` своего или чужого контрола. Она дойдёт до драйвера или до `on_command`, как команда любого другого сервиса. Если же записать через `client.raw` прямо в топик значения, объект этого не увидит, и значение в нём останется прежним.

Отдельного метода для удаления топиков нет. Чтобы стереть топик, опубликуйте в него пустое retained-сообщение. Много топиков по маске можно стереть так:

```python
for topic in await client.raw.read("/devices/old_device/#"):
    await client.raw.publish(topic, "", retain=True)
```

Если обработчик нужен только для одного ответа, снимите его сразу после ответа. Иначе после каждого запроса на фильтре будет оставаться ещё одна функция.

```python
async def scan(client: Client, seconds: int) -> Any:
    answer = asyncio.get_running_loop().create_future()

    async def on_response(message: Message) -> None:
        if not answer.done():
            answer.set_result(json.loads(message.payload))

    await client.raw.subscribe("gateway/response/scan", on_response)
    try:
        await client.raw.publish("gateway/request/scan", json.dumps({"time": seconds}))
        return await asyncio.wait_for(answer, 10)
    finally:
        await client.raw.unsubscribe(on_response)
```

## Ошибки

| Ошибка                    | Когда                                                                                                                                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BrokerDisconnectedError` | вызову нужен ответ брокера, а связи нет или брокер не ответил вовремя. Такие вызовы читают брокер, например `create_device` и `get_control`, или отправляют сообщения без retain, то есть команды и нажатия |
| `NotOwnError`             | действие, которое разрешено только для своего устройства, вызвали для чужого, например `set_error` или `on_command`                                                                                         |
| `ReadonlyControlError`    | `set_value` чужого контрола с `readonly`                                                                                                                                                                    |
| `ControlMissingError`     | действие с контролом, которого сейчас нет, или со своим устройством после его `remove()`                                                                                                                    |
| `DeviceTakenError`        | `create_device` без `force`, когда имя занято устройством другого драйвера                                                                                                                                  |
| `AlreadyCreatedError`     | повторный `create_device` или `create_control` того же устройства или контрола этим клиентом                                                                                                                |
| `InvalidNameError`        | неверное имя устройства, контрола или драйвера, адрес контрола без `/`                                                                                                                                      |
| `LoginRejectedError`      | брокер отверг логин при первом подключении                                                                                                                                                                  |
| `ClientClosedError`       | вызов после `close()` или ожидание брокера, которое прервал `close()`                                                                                                                                       |
| `TimeoutError`            | нужное значение, контрол или устройство не появились за `timeout`                                                                                                                                           |
| `ValueError`              | неверный топик, QoS, значение поля меты, тип контрола или адрес брокера, второй клиент с тем же драйвером в процессе                                                                                        |
| `TypeError`               | значение не подходит к типу контрола, у аргумента не тот тип, неизвестное поле меты, у обработчика не то число аргументов                                                                                   |
| `RuntimeError`            | повторный `connect()` подключённого клиента                                                                                                                                                                 |

Собственные ошибки библиотеки наследуют `MqttLibError`, а `DeviceTakenError`, `AlreadyCreatedError` и `InvalidNameError` ещё и `ValueError`. Остальные ошибки в таблице это стандартные исключения Python. `TypeError` и `RuntimeError` означают ошибку в коде сервиса, ловить их не нужно. Исключения aiomqtt до сервиса не доходят.

Если обработчик бросил исключение, библиотека пишет его в лог и передаёт обработчику следующие события. Вне обработчиков исключение доходит до вызывающего кода, как у любой функции.

## Логи

Библиотека пишет в стандартный `logging`, вывод настраивает сервис. Свои уровни библиотека не задаёт, поэтому её логи идут на том же уровне, что и логи сервиса. Обрыв связи клиент пишет одной строкой WARNING, подробности работы идут на уровне DEBUG.

Чтобы задать уровень для всей библиотеки отдельно от сервиса, настройте один логгер `wb.<сервис>.wb_mqtt_lib`, остальные логгеры библиотеки дочерние. Например, так включается DEBUG только для библиотеки при общем уровне INFO.

```python
logging.basicConfig(level=logging.INFO)
logging.getLogger("wb.mqtt_example.wb_mqtt_lib").setLevel(logging.DEBUG)
```
