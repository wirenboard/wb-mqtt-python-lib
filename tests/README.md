# Тесты

## Запуск

Из корня репозитория.

```bash
python3 -m pytest
```

## Что нужно

Debian trixie или контейнер `debian:trixie` с пакетами `mosquitto`, `python3-asyncio-mqtt`, `python3-pytest`, `python3-pytest-asyncio` и `python3-pytest-timeout`. Версии те же, что на контроллере, ставить зависимости через pip не нужно.

Контроллер и общий брокер не нужны, каждый тест запускает свой mosquitto на свободных портах. Брокер настоящий, потому что взаимные блокировки и переподключение на заглушках не ловятся.

## Как устроено

- `conftest.py` — фикстуры. `broker` запускает mosquitto, `client` это сервис под тестом, `driver` другой сервис на том же брокере, `connect` подключает клиента по tcp, unix-сокету или websockets, `dead_link` подключает его через прокси, который изображает мёртвую связь.
- `broker.py` — помощники тестов. Это брокер с настройками контроллера и его перезапуск, обрыв связи, задержка и потеря PUBACK, ожидание нужного состояния брокера и счётчики внутри клиента для поиска утечек.
- `pytest.ini` — таймаут 60 с на тест.

Ожидания в тестах идут через `wait_or_dump`. Если результата нет, тест падает с `DeadlockSuspectedError`, и в сообщении видна цепочка корутин каждой задачи.

## Что покрыто

| Файл                      | Что проверяет                                                    |
| ------------------------- | ---------------------------------------------------------------- |
| `test_own_devices.py`     | свои устройства, создание, значения, команды и удаление этапами |
| `test_values.py`          | проверку и формат значений и объявлений контролов                |
| `test_foreign_devices.py` | чтение чужих устройств, снимки и разбор чужой меты               |
| `test_listeners.py`       | обработчики событий и `wait_value`                               |
| `test_ownership.py`       | объекты по имени и смену владельца имени                         |
| `test_lifecycle.py`       | `connect()` и `close()`                                          |
| `test_reconnect.py`       | перезапуски брокера, мёртвую связь и повтор своего состояния     |
| `test_deadlocks.py`       | обработчики, которые сами ждут брокер                            |
| `test_multiple_clients.py`| несколько клиентов в одном процессе                              |
| `test_leaks.py`           | утечки памяти, задач и подписок при долгой работе                |
| `test_direct.py`          | `client.direct`                                                  |
| `test_transports.py`      | транспорты, адрес брокера и логин                                |
| `test_package.py`         | что внутри библиотеки только относительные импорты               |
| `test_broker.py`          | сами помощники и детектор зависаний                              |

Что проверяет каждый тест, написано в его докстринге.
